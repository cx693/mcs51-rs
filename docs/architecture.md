# 架构与验证

## 1. 分层

```
                      ┌──────────────────────────────┐
   mcs51.toml  ──────▶│  mcs51-build  (mcs51 CLI)     │
                      └───────┬──────────────┬────────┘
                              │              │
              ┌───────────────▼───┐   ┌──────▼─────────┐
              │  mcs51-codegen    │   │  mcs51-sim     │
              │  (asm 源 + 构建)   │   │  Timer/UART/IO │
              └───────┬───────────┘   └──────┬─────────┘
                      │                      │ i8051 CPU 核
              ┌───────▼───────┐              │
              │  mcs51-asm    │              │
              │  汇编器        │              │
              └───────┬───────┘              │
                      │                      │
              ┌───────▼───────┐              │
              │  mcs51-ld     │──────────────┘
              │  链接器        │   (周期数来自同一张表)
              └───────┬───────┘
                      │
              ┌───────▼───────┐
              │  mcs51-ihex   │
              └───────┬───────┘
                      │
              ┌───────▼───────────────────────────┐
              │  mcs51-isa  (no_std, 单一事实来源) │
              │  操作码表 / 编解码 / SFR / 内存模型 │
              └───────────────────────────────────┘
```

依赖方向是单向的：`mcs51-isa` 不依赖任何其它 crate，`mcs51-codegen` 依赖整条链。
`mcs51-isa` 只有一个 `dev-dependency`（`i8051`，仅用于交叉验证）。

## 2. 为什么把指令集单独抽出来

操作码表同时被四个消费者使用，任何不一致都会产生难查的 bug：

| 消费者 | 用到的字段 |
|---|---|
| 汇编器 | `args`、`enc`（编码位置）、`base`、`embed_mask` |
| 反汇编器 | `args`、`enc`（解码）、`embed_mask`（族展开） |
| 模拟器 | `cycles`（周期计数） |
| 报告 / 分析 | `cycles`、`flags`、`class()` |

把表放在 `no_std` crate 里还有一个实际好处：**同一份代码可以在目标机上运行时反汇编**。
例如固件可以在启动时对自己做校验、或者在串口 shell 里反汇编任意地址。

表本身的表达方式：

```rust
op!(0x85, Mov, 2, F_NONE, [Direct => byte(2), Direct => byte(1)]),
//   ▲     ▲   ▲   ▲        ▲                  ▲
//   │     │   │   │        │                  └─ 源操作数在第 1 字节
//   │     │   │   │        └──────────────────── 目的操作数在第 2 字节
//   │     │   │   └───────────────────────────── PSW 影响标志
//   │     │   └───────────────────────────────── 机器周期
//   │     └───────────────────────────────────── 操作数形状
//   └─────────────────────────────────────────── 基操作码
```

有可变位的族只写一条（`0x08 | n` 写作 `op!(0x08, Inc, 1, F_NONE, [Rn => L3])`），
`embed_mask()` 从中恢复掩码，`variant_count()` / `variant(n)` 负责展开。

## 3. 汇编器：为什么两遍就够

8051 的一个关键性质是：**指令长度与操作数值无关**。`SJMP label` 永远是 2 字节，
`LJMP label` 永远是 3 字节，不存在 x86 那种「短跳/长跳」需要松弛的情况。

因此：

1. **定址遍**：只算大小、只登记标签地址，不解析操作数值。因为大小固定，
   一次遍历就能给所有标签定出正确地址。
2. **发射遍**：此时文件内所有符号都已知，可以直接算出常量；只有**跨目标**引用
   或**可重定位段之间**的引用才生成重定位项。

对于 `.equ` 前向引用、`.org` 依赖等情况，定址遍会**迭代到收敛**
（`max_passes`，默认 5 次），每轮重新计算段大小与符号表，直到不再变化。

相对跳转的优化：如果目标符号与当前指令在**同一个段**内，位移与段的最终落址无关，
因此汇编期就能算出 `rel`，不必留给链接器。这在实践中能消掉绝大多数 `REL8` 重定位。

## 5. 验证策略

### 5.1 三层验证

| 层 | 手段 | 覆盖 |
|---|---|---|
| 指令集 | 与 `i8051` 独立实现逐条对拍 | 9216 个组合，255 个操作码，编解码往返 |
| 工具链 | 汇编 → 反汇编往返、链接器符号/重定位断言 | 每个操作码都有源码写法，跨目标符号解析 |
| 系统 | 在模拟器里跑真实固件并断言行为 | 点灯顺序与时序、串口输出、静态变量落在合法 RAM |

裸机固件最容易出的两类错都在**构建期**被挡住了：

* 内部 RAM 分配越界（`App::statics` 绝不越过栈底，也绝不落进 SFR 区）
* 生成的汇编本身通不过汇编器 —— 那说明是 codegen 的 bug，会被直接报出来，
  而不是烧进芯片才发现

### 5.2 为什么 orcale 用 `i8051` 而不是自己写两份

自己写两份同样的表，很可能**犯同样的错**。`i8051` 是第三方独立编写的模拟器
（作者 Matt Mastracci），它的操作码表是另一条思路的产物，作为 oracle 才有意义。
它只作为 `dev-dependency`，不进入交付产物。

### 5.3 测试抓到过的真实 bug

见 README 的「测试驱动发现的真实 bug」表。这些 bug 的共性是：
**单看代码看不出问题，必须靠行为断言才能暴露**。例如：

* 汇编器的字符串转义不认识 `\xNN` → 现象是串口打出来的换行变成字面文本
  `x0D`。只有逐字节核对串口输出才看得出来。
* `App::statics` 把应用变量放到 `0xD0` → 模拟器里一切正常（它把 SFR 空洞
  当普通内存），真机上 P3.7 完全不动。8051 的直接寻址空间里 `0x80` 以上
  全是 SFR，这条规则必须由构建期检查守住。

## 6. 扩展点

* **新器件**：往 `crates/mcs51-chips` 加一个模块（见该 crate 的文档）
* **新外设**：往 `crates/mcs51-codegen/src/hal.rs` 加一个对象。约定是
  「主机侧算好常量 + 一个 `begin()` 把 SFR 配到位」，并且**所有对共用寄存器的
  写入都要读-改-写**（`TMOD`、`PCON` 这类寄存器一半的位属于别的外设）
* **新链接布局**：写一个 `.lk`，不需要改代码
* **新外设**：在 `mcs51-sim/src/` 加模块，并在 `Peripherals::apply` 里接管对应 SFR
* **多文件工程**：`.globl` / `.extern` 已支持，`sources` 数组按顺序链接
* **新目标架构**：`mcs51-isa` 的表结构是通用的（`args`/`enc`/`embed_mask`），
  换一张表就能描述别的 8 位机后端
